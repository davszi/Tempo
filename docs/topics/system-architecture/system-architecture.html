TEMPO System Architecture

The Python application uses SQLite to share practice history between Learning and Repeating. An offline training pipeline supplies the general model used by the review planner.

Components and data flow

Figure 1 shows how the controllers exchange data and how the trained model reaches the ML engine.

Learning and Repeating

Learning

The player chooses a line. The Practice controller loads it and the board shows the expected move with an arrow. A correct move advances the line. A wrong move keeps the same position for a guided retry. Completing the session adds the line to the player’s repertoire.

Repeating

The planner chooses a due line and the app opens it automatically. The player recalls the moves without hints. A wrong move is taken back immediately so the player can retry from the same position.

Review scheduling

An empty repertoire directs the player to Learning. A player who has learned a line can receive a first suggestion from the initial FSRS schedules. The planner picks the most overdue line and uses the earliest learned line to break ties. When nothing is due, the UI shows that state.

The first Learning completion makes the line due immediately. After Repeating, the ML engine grades the recorded moves and uses Py-FSRS to calculate stability and the next review date.

Component responsibilities

Chess UI
Shows the board, line selection, Learning arrows, and Repeating feedback.
Practice controller
Loads lines, starts sessions, checks moves, and records practice events.
SQLite
Stores opening lines, real player practice history, and past suggestions.
ML controller
Fetches the player’s repertoire, practice history, and suggestions, calls the engine, and records the suggested line.
ML engine
Chooses a due line, grades completed reviews, and uses Py-FSRS to update stability and the due date.
Offline data
Generates synthetic reviews for training. The demo uses a supplied FSRS weights file.

Run the demo

From the repo root in PowerShell, run .\run-demo.cmd for a clean review or .\run-demo.cmd --side black --grade Again to show a wrong move and retry.

Open demo/tempo_demo.sqlite in DB Browser for SQLite and filter practice_events and player_lines by the player ID printed by the demo.
